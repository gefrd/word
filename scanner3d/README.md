# Kivu 3D Scan

3D-сканер для телефона, работающий прямо в браузере (PWA): без сервера, после первой загрузки — без интернета.

## Режимы

| Режим | Как работает | Телефоны | Интернет |
|---|---|---|---|
| **Скан без листа** (главный режим: живая камера, видео или 15–40 фото) | ИИ (RMBG‑1.4) выделяет предмет на каждом кадре; по точкам на самом предмете вычисляются положения камеры (structure from motion, всё своё, без библиотек); затем тот же «вырезанный объём», что и в режиме с листом. Работает и когда обходите предмет, и когда предмет крутится на табурете перед неподвижным телефоном | любые; ≤ 2 ГБ — облегчённые настройки | только при первом запуске (~45 МБ модели, та же, что у «Фото → 3D») |
| **Точный режим (лист с метками)** (живая камера, видео или 15–40 фото) | Предмет стоит на листе A4 с 10 метками ArUco. По меткам вычисляется положение камеры в каждом кадре, затем «вырезается» объём (voxel carving), строится гладкая поверхность и раскрашивается по кадрам | любые, включая бюджетные | не нужен |
| **Фото → 3D (ИИ)** | RMBG‑1.4 выделяет предмет, Depth Anything V2 Small даёт карту глубины, из них строится замкнутый объёмный рельеф с текстурой | любые; с WebGPU (Pixel) быстрее | только при первом запуске (~70 МБ моделей) |
| **Просмотр и AR** | вращение пальцем; AR на столе через WebXR (Android с ARCore), AR Quick Look (iPhone), «AR‑камера» с гироскопом для всех остальных | любые | не нужен |

Экспорт: GLB (для AR, 3D-просмотрщиков, игр; в метрах и реальном размере), STL (3D-печать, мм), OBJ с цветами вершин. Модели можно сохранить в «Мои модели» (IndexedDB на телефоне).

Настройки подстраиваются под устройство (`navigator.deviceMemory`): на телефонах ≤ 2 ГБ используются меньшие кадры и более крупные воксели.

## Запуск и сборка

```bash
cd scanner3d
npm install
npm run dev       # http://localhost:5173, --host для доступа с телефона в той же Wi‑Fi
npm run build     # готовый сайт в dist/ (~2.4 МБ)
```

Камера в браузере работает **только по HTTPS** (или на localhost). `dist/` можно положить в любую папку любого HTTPS-хостинга — пути относительные (например, `https://kivu.site/scan3d/`).

## Как сканировать без листа

1. «Scan with camera»: медленно обойдите предмет по кругу (лучше два круга — пониже и повыше). Кадры снимаются сами; «Done» — от 12 кадров, лучше 25–40.
2. Или снимите видео 20–40 с (обход или предмет, который медленно поворачивают на табурете на полный оборот), или 15–40 фото со всех сторон.
3. Размер без листа — оценка (считается, что телефон был примерно в 40 см). Введите реальную длину в поле «Real length» — модель масштабируется точно.

Лучше всего получаются предметы с рисунком (кроссовки, сумки, игрушки, бутылки с этикеткой). Однотонные белые, блестящие и прозрачные предметы могут не получиться — тогда приложение предложит «Фото → 3D».

## Как сканировать с листом

1. Откройте «Лист с метками» → «Скачать PDF», напечатайте на A4 **в масштабе 100 %**. Нет принтера — покажите лист на экране ноутбука/планшета, положенного горизонтально (форма будет верной, масштаб — нет).
2. Поставьте предмет в пунктирную рамку. Предмет не должен быть белым; прозрачные и зеркальные не получатся.
3. «Сканировать камерой»: обойдите предмет тремя кругами — низко, под ~45° и сверху. Кадры снимаются автоматически, купол внизу показывает, какие ракурсы уже есть. Нажмите «Готово» (от 10 кадров, лучше 25–36).

## Устройство кода

| Файл | Что делает |
|---|---|
| `src/board.js` | раскладка листа, SVG |
| `src/sheet-pdf.js` | векторный PDF листа без библиотек |
| `src/vendor/aruco.js` | js-aruco2 (MIT) в виде ES-модуля |
| `src/geometry.js` | гомография, оценка фокуса по всем кадрам, поза камеры (Левенберг–Марквардт) |
| `src/tracker.js` | метки → соответствия → поза, отбраковка ошибочных меток |
| `src/capture.js` | живая камера с автозахватом по покрытию, импорт видео и фото |
| `src/features.js` | свои FAST-углы + двоичные дескрипторы BRIEF на пирамиде, сопоставление по Хэммингу |
| `src/fivepoint.js`, `src/p3p.js` | 5‑точечный алгоритм Нистера (относительная поза), P3P + RANSAC (поза по 3D-точкам) |
| `src/sfm.js` | structure from motion: пары кадров, треки, выбор начальной пары по третьему кадру, регистрация кадров, разреженная связка (Левенберг–Марквардт с дополнением Шура), замыкание круга, проверка фокуса |
| `src/rmbg.js` | маски RMBG‑1.4 через onnxruntime-web; вход модели «размораживается» в памяти, чтобы считать на ~384 px вместо 1024 (в ~15 раз быстрее) |
| `src/markerless.js`, `src/markerless.worker.js`, `src/markerless-client.js` | режим без листа: система координат предмета (верх, центр, масштаб, пол), грубое → точное вырезание объёма, всё в Web Worker |
| `src/refine.js`, `src/depth.js` | эксперимент (галочка на главном экране, по умолчанию выкл.): досечение объёма по согласованности цвета между кадрами и по карте глубины Depth Anything V2 |
| `src/maskfix.js` | проверка и исправление масок ИИ: пересчёт на кадре, обрезанном вокруг предмета; неподвижные пиксели при съёмке на табурете |
| `src/reconstruct.js` | сегментация по листу + цветовая модель фона, вырезание объёма, surface nets, сглаживание, раскраска с учётом видимости; потоковая обработка (кадры по одному — мало памяти) |
| `src/recon.worker.js` | реконструкция в Web Worker (есть запасной путь в основном потоке для iOS < 16.4) |
| `src/photo3d.js`, `src/photo3d.worker.js` | ИИ-режим (transformers.js / ONNX Runtime Web) |
| `src/viewer.js` | просмотр, WebXR, Quick Look, AR-камера |
| `src/export.js` | GLB / USDZ / STL / OBJ |

## Тесты

Автотесты используют синтетическую сцену three.js (лист, стол с посторонними предметами, кружка с ручкой, шар, куб, тени):

```bash
npx vite --port 5190 &                # dev-сервер для тестовых страниц
node test/run-pose.mjs                # распознавание меток и поз (ошибка ~3 мм)
node test/run-recon.mjs --el=15,35,60 --n=30   # реконструкция против эталона: IoU ≈ 0.93
npx vite build && npx vite preview --port 5191 &
node test/mk-video.mjs && node test/e2e-video.mjs    # видео → модель через интерфейс
node test/mk-mjpeg.mjs && node test/e2e-live.mjs     # живая камера (фальшивая камера Chromium)
```

`test/e2e-photo.mjs` ожидает веса RMBG в `test/models/briaai/RMBG-1.4/onnx/model_quantized.onnx` (пакет npm `@rmbg/model-briaai`, склеить 5 частей) и подменяет запросы к Hugging Face локальными файлами.

Тесты режима без листа (синтетическая сцена без листа: кроссовок / игрушка / бутылка на столе, обход по кругу и вращение на табурете):

```bash
NO_HMR=1 npx vite --port 5190 &
node test/run-free.mjs --obj=sneaker --mode=walk --masks=rmbg --maskEval --gtPoses   # одна сцена, подробно
node test/run-free-matrix.mjs --masks=rmbg                                           # таблица по всем сценам
node test/run-free.mjs --obj=mug --loops=25,50 --masks=rmbg --refine --depth         # досечение (цвет + имитация сети глубины)
npx vite build --outDir /tmp/k3d && npx vite preview --port 5191 --outDir /tmp/k3d &
node test/e2e-free.mjs --input=video [--noseek] [--cpu=4]                            # через интерфейс
```

## Ограничения

- Метод силуэтов не видит вогнутостей, закрытых со всех сторон (внутренность чашки, углубления).
- «Фото → 3D» даёт объёмный рельеф: задняя сторона достраивается, а не снимается.
- Лицензии моделей ИИ: RMBG‑1.4 — только некоммерческое использование; Depth Anything V2 Small — Apache‑2.0.
